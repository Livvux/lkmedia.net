Rank Math unterstützt die technische SEO-Konfiguration einer WordPress-Website. Entscheidend ist die tatsächlich ausgegebene Seite: Titel, Canonical, Indexierbarkeit und strukturierte Daten müssen zum Inhalt passen. Ein hoher Plugin-Score ist kein Nachweis für gute Rankings.

Die folgenden Grafiken sind Einstellungs-Schemata. Sie zeigen Zusammenhänge, keine Screenshots einer bestimmten Plugin-Version. Menünamen und verfügbare Funktionen können sich ändern; prüfen Sie bei Abweichungen die verlinkte Herstellerdokumentation.

## 1. Vor dem Setup: Backup und Zuständigkeit

Sichern Sie Website und Datenbank vor einem Wechsel des SEO-Plugins. Prüfen Sie, welches Plugin derzeit Titel, Sitemap und strukturierte Daten erzeugt. Mehrere gleichzeitig aktive SEO-Ausgaben können doppelte oder widersprüchliche Tags erzeugen.

Bei einer Migration sollten vorhandene Metadaten und Weiterleitungen übernommen werden. Kontrollieren Sie einige wichtige Seiten vor und nach dem Wechsel. Ein Export hilft bei der Rückkehr zum bisherigen Zustand, falls die Migration unvollständig ist.

## 2. Module nach Bedarf aktivieren

Nicht jede Website benötigt jede Funktion. Ein Blog hat andere Anforderungen als ein Shop oder eine mehrsprachige Unternehmenswebsite. Aktivieren Sie nur Funktionen, deren Ausgabe und Pflege Sie beurteilen können.

![Einstellungs-Schema: Module nach Bedarf auswählen](/posts/rankmath/rankmath-modules.svg)

Die [Dokumentation zum erweiterten Modus](https://rankmath.com/kb/advanced-mode/) erklärt, welche Optionen der Hersteller dort bereitstellt. Prüfen Sie die installierte Version und Ihren Tarif, statt eine ältere Featureliste ungeprüft zu übernehmen.

## 3. Titel, Beschreibungen und Canonicals

Erstellen Sie für jeden wichtigen Seitentyp eine sinnvolle Vorlage. Schreiben Sie für zentrale Angebotsseiten individuelle Titel und Beschreibungen. Besucher sollten erkennen, welche Leistung sie auf der Seite finden und für wen sie gedacht ist.

![Einstellungs-Schema: Titel, Beschreibung und Suchvorschau prüfen](/posts/rankmath/rankmath-titles-meta-settings.svg)

Prüfen Sie anschließend den Quelltext der veröffentlichten Seite:

- Gibt es genau einen passenden Title?
- Beschreibt die Meta-Description den tatsächlichen Inhalt?
- Verweist der Canonical auf die gewünschte indexierbare URL?
- Ist versehentlich ein noindex gesetzt?
- Sind Social-Media-Bild und URL absolut und erreichbar?

Eine Vorschau im Plugin garantiert nicht, dass Google denselben Text als Snippet verwendet. Der sichtbare Inhalt und die Suchanfrage spielen ebenfalls eine Rolle.

## 4. Sitemap und Indexierung prüfen

Die Sitemap sollte die URLs enthalten, die Sie zur Indexierung anbieten möchten. Persönliche Bestätigungsseiten, interne Suchergebnisse oder bewusst ausgeschlossene Inhalte gehören dort nicht hinein. Vergleichen Sie die erzeugte Sitemap mit den tatsächlich erreichbaren Seiten.

Die [Rank-Math-Anleitung zur Sitemap](https://rankmath.com/kb/configure-sitemaps/) beschreibt die Konfiguration. Reichen Sie die fertige Sitemap in der passenden Search-Console-Property ein. Eine erfolgreiche Einreichung bedeutet, dass Google die Sitemap abrufen konnte; sie ist keine Indexierungszusage.

Öffnen Sie einzelne URLs zusätzlich mit der URL-Prüfung der Search Console. Prüfen Sie insbesondere Canonical, Indexierungsstatus und mögliche Abruffehler.

## 5. Strukturierte Daten passend zum Inhalt

Ein Artikel kann als Article beziehungsweise BlogPosting beschrieben werden. Ein tatsächliches Angebot braucht passende Angebotsdaten. Unternehmensangaben müssen mit der sichtbaren Website übereinstimmen.

![Einstellungs-Schema: Datentyp und belegbare Angaben abstimmen](/posts/rankmath/rankmath-schema-settings.svg)

Fügen Sie keine erfundenen Bewertungen, Qualifikationen oder Ergebnisse hinzu. Prüfen Sie außerdem, ob Theme, andere Plugins oder individuell eingebauter Code bereits Schema erzeugen. Die Ausgabe sollte nicht mehrere widersprüchliche Beschreibungen derselben Organisation enthalten.

Die [Dokumentation zu strukturierten Daten von Google](https://developers.google.com/search/docs/appearance/structured-data/intro-structured-data) erklärt die Grundlagen. Korrektes Markup garantiert keine besondere Darstellung in den Suchergebnissen.

## 6. Inhalte vor dem Score optimieren

Die wichtigste Frage lautet: Hilft diese Seite dem Besucher bei seiner Entscheidung? Ein Text kann häufig ein Keyword wiederholen und trotzdem unverständlich bleiben. Ebenso ersetzt eine vorgegebene Wortzahl keine vollständige Antwort.

![Einstellungs-Schema: Suchintention, Links und Lesbarkeit prüfen](/posts/rankmath/rankmath-content-editor.svg)

Prüfen Sie Überschriften, verständliche Absätze, echte Beispiele und sinnvolle interne Links. Verlinken Sie direkt zur passenden Angebotsseite. Ein Artikel über die Kosten einer Kanzlei-Website sollte beispielsweise auf [Webdesign für Anwaltskanzleien](/anwaelte) und den [Kostenratgeber](/blog/kanzlei-website-kosten/) führen.

## 7. Weiterleitungen und echte 404

Eine 301-Weiterleitung gehört zu einer dauerhaft verschobenen Seite mit einem passenden Nachfolger. Leiten Sie nicht sämtliche unbekannten URLs auf die Startseite oder den Blog um. Entfernte Inhalte ohne Ersatz dürfen einen echten 404-Status liefern.

Testen Sie geänderte URLs mit ihrem HTTP-Status und vermeiden Sie unnötige Ketten. Prüfen Sie auch interne Links: Ihre eigene Navigation sollte direkt auf die aktuelle Zielseite zeigen.

## 8. Messung von der Konfiguration trennen

Search Console zeigt unter anderem Suchklicks, Impressionen und Indexierungsinformationen. Ein Analytics-System zeigt die Nutzung Ihrer Website. Diese Daten beantworten unterschiedliche Fragen und benötigen getrennte Zugriffs- und Datenschutzeinstellungen.

![Einstellungs-Schema: Suchdaten und Nutzungsdaten getrennt prüfen](/posts/rankmath/rankmath-analytics-integration.svg)

Verknüpfen Sie nur Konten, für die Sie berechtigt sind. Zugangsdaten, personenbezogene Formularinhalte und private Bestätigungslinks gehören nicht in Analytics-Ereignisse.

## Checkliste nach dem Setup

1. Startseite, Angebotsseite und Artikel im echten Browser öffnen.
2. Titel, Canonical, robots-Tags und Social-Media-Vorschau prüfen.
3. Sitemap und einige darin enthaltene URLs abrufen.
4. Strukturierte Daten aus der gerenderten Seite validieren.
5. Bekannte alte URLs und eine erfundene URL testen.
6. Mobilen Seitenaufbau und wichtige Kontaktwege prüfen.
7. Ausgangswerte festhalten und Veränderungen über vergleichbare Zeiträume messen.

Für die Performanceprüfung können Sie [Google PageSpeed Insights](https://pagespeed.web.dev/) nutzen. Labormessungen und verfügbare Felddaten sind getrennt zu betrachten. Ein einzelner Lighthouse-Lauf belegt keine Core Web Vitals aller Besucher.
